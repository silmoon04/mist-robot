01

Read this before opening Fusion

Set the authority order, coordinate system, and completion standard before geometry starts.

The fastest way to lose a week in CAD is to make a clean bracket around a guessed interface. MIST therefore separates what is frozen, what must be measured, what is merely a starting value, and what Fusion calculates.

This is a build procedure, not a certification.

The repository contains planning, simulation, dimension, and historical mesh evidence, but no verified native MIST .f3d/.f3z assembly or released printable set. Do not mark a stage complete because its illustration looks plausible.

The four labels used everywhere

Locked

Project contract

Use as written unless you deliberately revise the master dimensions and all downstream checks. Examples: body_dia = 180 mm, link lengths, mount azimuths, and joint limits.

Measure

Physical interface

Replace from calipers before cutting mating geometry. Examples: servo ears, spline, horn bolt circle, wheel hub, connectors, and the phone with its real case.

Provisional

Testable assumption

A safe place to begin a coupon or layout study, not a released dimension. Examples: shell wall, pocket clearance, ribs, lid seam, bearing support, cable slots.

Derived values such as radii, pocket sizes, joint coordinates, and solved angles must be expressions. Never type a second independent copy of a number that already has a named source.

Authority order

  1. Physical caliper measurements and printed coupon results.
  2. The current MIST Fusion master-dimension contract.
  3. The simulator kinematics for axes, frames, and sign conventions.
  4. Current inventory, material, wiring, build-phase, and print-test documents.
  5. Older variant reports and meshes, used only to learn from failures.
  6. The six original AI posters and their AI-assisted derivatives, used only as visual scaffolding. Exact geometry and claims live in deterministic diagrams, searchable HTML, measured records, and test outputs.

If two sources disagree, stop at the higher-authority source. Record the conflict; do not average the numbers.

Coordinate and naming contract

Robot frame

+X is forward, +Y is robot-left, and +Z is up. Put the global origin on the body centreline at the nominal cylinder bottom. Model the body upward from Z = 0.

Leg names and IDs

FL front-left, FR front-right, RL rear-left, RR rear-right. Analytic arrays use FL, FR, RL, RR; the physical ID/export blocks use FL 1–4, FR 5–8, RR 9–12, RL 13–16. Keep that explicit boundary in Browser notes, drawings, firmware and harness labels.

Joint chain

base_link → q1 → d1 → q2 → femur → q3 → tibia → wheel. The wheel is a driven revolute axis, not a decorative foot.

Angle convention

Mount azimuth is measured from +X toward +Y. The four physical rays are +25°, −25°, +109°, and −109°.

Use a reversible build loop

MeasureCalipers, mass, connector and cable exit.
EnvelopeSimple named construction bodies.
SkeletonAxes, reach, mount rays, keep-outs.
InterfaceCoupons before full brackets.
ValidateMotion, collisions, print, assembly.
ReleaseNative, STEP, 3MF, drawings, manifest.
Freeze interfaces later than envelopes.

You can place a servo-sized box and reserve its cable volume immediately. You should not cut its ear slots, spline fit, or horn bolt pattern until the received unit is measured.

Why one Hybrid Design first?

It makes expression wiring, projection, Timeline rollback, and joint inspection easier for a first full build. A distributed workflow is better when several people own stable parts or when the assembly becomes too heavy. If you migrate, derive only intentional master geometry, give every external component an owner and version, then test updates in a branch file.

Copy, Paste New, or Duplicate With Joints?
  • Copy + Paste normally creates another occurrence of the same component definition; an edit propagates.
  • Paste New makes an independent definition; use only when divergence is deliberate.
  • Duplicate With Joints is the preferred current assembly tool for repeated articulated legs because it copies the component structure and relationship pattern. Validate names and orientation afterward.

Small navigation habits that prevent large mistakes

  • Click a ViewCube face before dimensioning a 2D layout. Use Home to recover a lost view.
  • Use middle-mouse pan/orbit/zoom settings consistently; never drag a component as a substitute for changing the view.
  • Press S and type the command name if a toolbar group moved.
  • Use Select filters when faces, sketches, joint origins, and components overlap.
  • Turn on only the component and reference bodies needed for the current decision.
  • At each stage, right-click the root and choose the compute/rebuild action available in the current build; then inspect the Timeline from left to right.

Construct the internal master skeleton

Create and activate 00_MASTER_LAYOUT. Make all skeleton sketches easy to identify—construction geometry, distinct colours if your theme supports it, and names beginning SK. Do not extrude a production body here.

SK00_TOP_MOUNTS on the XY plane

Sketch concentric construction circles for body_r, mount_r, hip_pitch_r, and stance_r. Add a construction line from the origin along +X. Add rays at front_az and rear_az, then mirror about the X axis for the right side. Put a point where each ray crosses the q1, q2, and stance circle. Fully constrain the sketch.

SK01_SIDE_KINEMATICS on the XZ plane

Draw the body bottom at Z = 0 and a ground line at Z = -neutral_body_clearance. Place q1 at (mount_r, leg_mount_h), q2 at (hip_pitch_r, leg_mount_h), and the wheel axis at (stance_r, wheel_r - neutral_body_clearance). Connect q2 to a knee point with femur, then to the wheel axis with tibia. Choose and document the outboard-knee solution branch.

SK02_FRONT_ENVELOPES on the YZ plane

Draw the body as body_dia × body_h. Draw the portrait phone pocket as phone_pocket_w × phone_pocket_h centred on Z = phone_center_z; at baseline this is 71.5 × 148.5 mm. Draw the provisional outer frame 77.5 × 154.5 mm. Add only labelled internal-zone and deck construction lines until component measurements are confirmed.

Fully constrained is necessary, not sufficient.

A black sketch can still encode the wrong branch or sign. Drag-test before final constraint, change stance_r by 1 mm, compute, undo, and confirm all four mount points and the intended knee branch move predictably.

Safe parameter-change protocol

  1. Save a new version and note the question the change is meant to answer.
  2. Change one user parameter or one controlled group—not a downstream feature dimension.
  3. Compute all. Resolve the earliest Timeline error first.
  4. Inspect SK00, SK01, and SK02 before inspecting pretty solids.
  5. Run the invalidation checks listed in the explorer chapter: reach, joint limits, body/leg collision, cable bend, print envelope, mass/CoM and interface coupons.
  6. Record the result, including a failed result, then keep or roll back deliberately.

Design the body around serviceable envelopes

Build the 180 × 260 mm chassis, four mount interfaces, phone carrier, electronics keep-outs, decks, seams, and cable routes without pretending unknown details are final.

The body is not a hollow cosmetic can. It is the load path between four legs, the heat and wiring volume for the power system, the phone support, and the main service access. Model it from the outside envelope inward, then prove every assembly and removal path.

The locked body envelope does not imply a one-piece print.

The nominal cylinder is 180 mm diameter × 260 mm high. A Neptune 4 Pro is nominally 225 × 225 × 265 mm, leaving only 5 mm of Z allowance before start/end layers, bed variation, brim, travel clearance, and profile margins. Use a segmented shell unless an actual calibrated print trial proves a one-piece strategy.

Separate the four kinds of body geometry

Envelope

What must fit

Body cylinder, nominal mount axes, phone and battery records, board/connector boxes, cable bends, fastener tools and hand access. Envelope bodies are named REF_* and excluded from manufacturing exports.

Structure

What carries load

Shell segments, leg-root bulkheads, decks, vertical webs, seam flanges and bosses. Start simple; add ribs where load paths and deflection show a reason.

Interfaces

What must mate

Servo ears/horns, inserts, battery straps, phone lips, lid seals, connectors and wheel supports. Their final cut geometry waits for a measurement or coupon result.

Model the canonical body envelope first

Activate 10_BODY_CHASSIS and project the contract

Start a sketch on the XY plane. Project the origin and body_r circle from SK00_TOP_MOUNTS. Draw a single centre-diameter circle constrained to body_dia; finish the sketch.

Extrude a reference cylinder

Extrude upward by body_h as a New Body and name it REF_body_envelope. Set its opacity and make it non-printing. This solid answers “where may the body exist?”; it is not the production shell.

Create the shell master

Copy the outer profile into a new production body, extrude to body_h, then Shell inward by shell_wall. Shell before detailed holes and fillets. If Shell fails after later edits, roll back and inspect the simple wall feature rather than patching faces.

Split for printing and service

Create offset construction planes for candidate seams, then Split Body. A conservative study layout is lower ≈85 mm, middle ≈90 mm, upper ≈85 mm; these are provisional and must move around leg loads, phone opening, decks and connectors. Keep each seam plane named and parameter-driven.

For a ring seam, add an internal overlap flange to one segment and a receiving land to the other. Use asymmetric keys so a segment cannot be installed rotated 180°. Do not put a seam through an unbroken load path.

A seam near the leg axes must transfer bending and torsion into a bulkhead/deck, not just through thin shell fasteners. Offset seams from the phone opening corners and reserve room for washers, inserts and a tool.

Place the four leg-root load paths

Project each explicit mount ray

Project the FL, FR, RL and RR q1-axis points and ray directions from SK00. Do not circular-pattern one mount by 90°; the rear pair is at ±109°, not ±90°.

Create a radial tangent datum

At each ray, create a construction plane tangent to the body envelope and parallel/oriented by the radial skeleton direction. Build mount pads and joint origins from these datums so azimuth changes remain coherent.

Connect mount to internal structure

Make the provisional external pad feed into two spaced shell ribs or a local bulkhead tied to a deck. Avoid a cantilevered boss attached only to 3 mm wall. Add generous root radii after the load path is stable.

Keep servo geometry separate

Insert the servo as a VERIFY envelope component and keep screw-head/plug access bodies visible. Final ears, horn, opposing support and cable slots remain blocked until measurement.

Create the phone envelope and service path

The baseline pocket expression gives 71.5 × 148.5 × 8.45 mm around the bare phone with 0.5 mm per-side clearance. The provisional outer frame is 77.5 × 154.5 mm. These do not include a case, camera bump, button relief, USB plug, retention lip or finger access.

Make a front datum plane

Create a plane tangent to the nominal front of REF_body_envelope, oriented from the global axes. Do not attach the phone sketch to a transient split-shell face or sketch directly on the cylinder.

Sketch the portrait opening

Project the Y and Z axes. Centre the pocket width on Y = 0 and its height on Z = phone_center_z. At baseline, top and bottom of the provisional outer frame are approximately Z = 247.25 and 92.75 mm. Check top-lid and lower-seam zones before cutting.

Use positive reference solids

Create REF_phone_bare, then separate keep-outs for the case/camera, side buttons, USB connector and cable bend. Use Combine/Cut only from copied or retained tool bodies so the evidence remains inspectable.

Prototype retention separately

Start with a cradle and removable retainer or strap, not a tiny snap inherited from the poster. Prove insertion, one-handed removal, button freedom, camera visibility, cable strain relief and retention under robot acceleration.

Arrange decks and cable corridors

  1. Place the battery envelope low, with strap and straight removal path.
  2. Place PDB, main 30 A fuse and XT90-S so high-current routing is short and inspectable.
  3. Reserve four branch paths toward the four leg roots. Each branch includes fuse holder, capacitor/root-tap volume, connector mating space, bend radius and service slack.
  4. Separate the signal harness from sharp edges and high-current bundles where practical. Reserve slack for full q1 motion.
  5. Put compute/sensor boards where USB, reset, programming and optical apertures remain accessible.
  6. Create decks only after the envelope layout passes. Use ribs or standoffs to connect deck loads into bulkheads, not arbitrary shell patches.
Reference power topology the CAD must make physically possible

battery → XT90-S → 30 A main fuse → PDB. The PDB feeds the UBEC/logic path and four separately fused leg branches, with the intended capacitor/root-tap volume near each leg. The Bus Servo Adapter carries signal and ground; it is not the main servo-current feed. Exact physical branch topology is still unresolved, so reserve modular corridors and access rather than moulding one guessed harness into the shell.

Mass properties are part of body design

Assign physical materials or calibrated custom densities to production bodies. When a simplified reference body omits internal mass, add a named hidden proxy body with calibrated density and keep it out of manufacturing exports; Fusion has no portable typed “component mass override” to rely on. Compare against the current 3.223 kg Layout A planning target and the broader 3.25–3.55 kg inventory estimate, but treat neither as a measured result. Sixteen servos alone are about 880 g, the battery about 174 g, the mounted phone package about 200–210 g, and electronics/harness planning is roughly 480–600 g. Use Inspect → Center of Mass in at least neutral, forward-lean and high-body poses.

Body audit before any full shell print

05

Build one honest four-axis leg

Model measured servo envelopes, load-bearing links, removable wheel hardware, stable joint origins, and cable space before making four copies.

A reusable leg is a small assembly, not one sculpted body. Each rigid link owns the servo case attached to it; the next link owns the driven horn interface. That ownership makes motion, print export, and maintenance understandable.

Material and process starting point

PETG structural baseline

Useful toughness and temperature margin for early chassis/links, but stringing, hole shrink, creep and layer adhesion are profile-dependent. Dry material, use adequate perimeters, and orient load paths deliberately.

TPU tyre / compliant parts

Useful for traction and isolation, but diameter changes under load and surface. Model the rigid wheel and tyre separately; measure loaded radius and lateral compliance before trusting stance or odometry.

Infill is not a substitute for section design

Perimeters, closed sections, ribs and layer orientation usually govern a thin structural part more directly than a high infill percentage. Document the actual slicer preview.

Support strategy changes interfaces

Support scars and bridging can alter mating faces. Reorient, split or add sacrificial machining stock before accepting support inside a bearing, servo or seam interface.

Why link thickness is so influential

For a simple rectangular beam, area moment of inertia about the strong axis is approximately I = b t³ / 12, and deflection scales roughly as δ ∝ L³ / (E b t³). This is a screening model, not a complete leg simulation, but it explains why increasing thickness from 14 to 15 mm can help more than the same 1 mm added to width—and why increasing femur length is expensive for stiffness.

Real links include servo pockets, bosses, anisotropic layers and changing sections. Validate with the link-root coupon and, later, a measured loaded assembly. Keep target load, fixture geometry, dial/measurement method and acceptance limit in the test record.

Current command routes

Native / neutral archive

File›Export

Select the intended F3D/F3Z or STEP type available in the current dialog. Cloud translation can require connectivity; wait for completion and inspect the downloaded file.

Printable mesh

Browser›right-click component/body›Save As Mesh / 3D Print

Select 3MF where supported, millimetres, the intended refinement, and only the production object. Open it in the actual slicer.

Drawing

Design›Drawing›From Design

Create inspection and assembly drawings from the release candidate; include axes and status notes, not every cosmetic dimension.

Print-export procedure

Create one manufacturing object per real part/material

Shell rings, lid, deck, phone frame, root adapter, links, wheel hub and tyre should not be fused merely to simplify export. Use quantities and handedness in names: MIST_FEMUR_v001_QTY4_PETG.

Apply intended orientation in a release layout

Use 90_RELEASE_LAYOUTS occurrences or slicer orientation instructions. Keep the source component’s engineering axes intact. Record which surface contacts the bed and which supports are expected.

Export 3MF and inspect in the real slicer

Confirm reported size, object count, normals/repair warnings, material assignment, first-layer footprint, brim, supports, bridges, thin-wall detection, seam placement, tool path around holes, estimated mass/time and printer bounds.

Round-trip a sample

Re-import or measure the exported object in an independent viewer/Fusion. Confirm millimetres and bounding dimensions. For each release batch, slice at least one representative complex part and one shell segment before publishing.

Release language rule

Say “passes the named CAD check” or “coupon result recorded,” not “safe,” “final,” or “fully validated,” unless the relevant mechanical, electrical, thermal, control and physical tests actually exist. Unchecked gates are useful engineering information.
