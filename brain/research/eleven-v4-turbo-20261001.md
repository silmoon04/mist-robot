# Eleven v4 Turbo: current API and expressive voice guidance

**Checked 2026-10-01.** Sources below are first-party ElevenLabs docs and API references. Current docs/changelog explicitly establish v4 Turbo support; some surrounding reference prose remains stale or v3-oriented.

## API route and model

- Model ID: `eleven_v4_turbo`. The September 28 changelog says v4 Turbo is for real-time applications, approximately 100 ms median inference latency, and directs agent/interactive use to the Text to Dialogue WebSocket. [September 28 changelog](https://elevenlabs.io/docs/es/changelog/2026/9/28) · [Models](https://elevenlabs.io/docs/overview/models)
- WebSocket: `wss://api.elevenlabs.io/v1/text-to-dialogue/stream-input?model_id=eleven_v4_turbo&output_format=...`; authenticate with `xi-api-key` header or first-message credential. First JSON frame registers `voices: [voice_id]`; subsequent frames send `inputs: [{text, voice_id, new_turn?}]`. Turbo accepts exactly one registered voice per connection. [Realtime TTD guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/realtime-tdd)
- This is not the legacy TTS WebSocket `/v1/text-to-speech/{voice_id}/stream-input`: official comparison says v4/v4 Turbo are supported on TTD, while TTS WS is for Flash/Multilingual and explicitly excludes v4. The comparison's summary sentence still calls TTD “v3 dialogue”; its models table and newer realtime guide explicitly allow `eleven_v4_turbo`. Treat the table/guide/changelog as the current authoritative correction. [TTS vs TTD](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/tts-vs-ttd-websockets)
- TTD buffers to about 40 characters / 8 words before first partial audio; `flush: true` forces short utterances. Use `new_turn: true` to reset turn prosody, `close_socket` to flush/end, `keep_alive` before its 20-second idle timeout. `sync_alignment=true` in the query enables alignment objects “when available”; it is optional and not guaranteed on every chunk. [Realtime TTD guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/realtime-tdd)
- “~100 ms” is vendor median inference latency, explicitly excluding application and network latency; it is not time-to-first-audio or end-to-end turn/playback latency. Include app buffering, transport, TTD's text threshold/flush, decoding, queueing, playback start, and robot output in a separate user-facing metric. Model page also gives Flash v2.5 ~75 ms on the same excluding-app/network basis, so Turbo should be evaluated for expressiveness, not presumed faster. [Models](https://elevenlabs.io/docs/overview/models)

## Voice settings and delivery control

- Generic voice-settings API documents scalar `stability` (0–1, default .5): lower gives broader emotional range/randomness; higher makes performance more consistent but can become monotonous. `similarity_boost` (0–1, default .75) controls fidelity to original voice; `style` (default 0) amplifies the source speaker’s existing style and can cost latency/stability; `speed` (default 1) controls rate; `use_speaker_boost` trades a little compute/latency for speaker similarity. [Edit voice settings API](https://elevenlabs.io/docs/api-reference/voices/settings/update)
- “Creative / Natural / Robust” are described in the older v3 prompting guide: Creative = most expressive but hallucination-prone; Natural = balanced/closest; Robust = most stable but less responsive to tags. The page is explicitly v3 alpha, so treat those labels as conceptual guidance rather than proof of a v4 Turbo mode/enum. For v4 Turbo, test numeric stability values and text tags; don’t send those names as API values. [Prompting guide](https://elevenlabs.io/docs/best-practices/prompting)
- In current v4/v4 Turbo docs, inline bracketed natural-language Audio Tags are the clearest delivery controls. Official September 30 tag guide says tags are open-vocabulary, work via API on `eleven_v4_turbo`, affect following text, can carry until changed, and may be combined. Useful MIST choices include `[curious]`, `[playful]`, `[amazed]`, `[thoughtful]`, `[confused]`, `[excited]`, `[softly]`, `[whispers]`, `[laughs]`, `[sighs]`, `[snappy]`, `[drawn out]`, `[pause]`. Use one clear tag per clause, change tags at the emotional pivot, and keep text context sufficient. These are directions, not guaranteed output labels. [Eleven v4 Audio Tags list](https://elevenlabs.io/hi/blog/elevenlabs-audio-tags-list)
- Tag guide says tags may be combined/described in plain language (e.g. `[nervous, trying to sound confident]`), but effectiveness varies by voice. Start with explicit emotion/delivery tags before escalating `style`; keep style at 0 for the first comparison because the API docs caution it can increase latency and instability. [Audio Tags](https://elevenlabs.io/hi/blog/elevenlabs-audio-tags-list) · [Settings API](https://elevenlabs.io/docs/api-reference/voices/settings/update)

## Voice choice, clone compatibility, and test setup

- The model overview says v4 Turbo has high-fidelity voice cloning. A voice is referenced by its regular `voice_id`; the TTD guide uses a Voice Library ID and does not require a special Turbo-only clone ID. Changelog also says a Professional Voice Clone's IVC version can optionally be used for Text to Dialogue to reduce latency or improve expressiveness (`use_pvc_as_ivc`, default false) on HTTP TTD endpoints. Do not assume that optional HTTP request field is supported in the WS first message unless the WS schema confirms it. [Models](https://elevenlabs.io/docs/overview/models) · [Changelog](https://elevenlabs.io/docs/es/changelog/2026/9/28) · [Voice cloning](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning)
- Generic voice guidance says created/cloned voices vary in emotional range; pre-made and voice-designed voices tend to be more tempered, cloned voices can express a wider range depending on source performance. Thus first test the already-account-accessible MIST clone as the identity-preserving primary. For public-voice exploration, official agent voice design suggestions characterize **Grandpa Spuds Oxley** (`NOpBlnGInO9m6vDvFkFC`) as a distinctive character voice and **Cassidy** (`56AoDkrOh6qfVPDXZ7Pt`) as engaging/energetic; these make useful character candidate and livelier control respectively, but neither description establishes quirky-robot suitability or v4 Turbo performance. Listen/test before choosing. [Voice design best practices](https://elevenlabs.io/docs/eleven-agents/customization/voice/best-practices/conversational-voice-design) · [Voice cloning overview](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning)
- Recommended small paired test: keep one MIST clone fixed; use the existing neutral stability as control, compare roughly `.35` and `.6` as expressive/steady numeric probes, hold similarity/speed fixed, style `0`, and compare untagged versus concise tags on identical scripts. Add Cassidy only as a public-voice expressiveness control; add Grandpa Spuds only as a character reference. Blind-score naturalness, identity, intelligibility, emotional fit, first audio, and complete playback separately. Values here are proposed experimental points, not official v4 presets.
- Pitfall: TTD's short-input buffer means a dialogue-phrase timing comparison with legacy TTS is unfair unless the test controls what triggers generation (buffer threshold vs explicit flush) and reports both model first-audio and full app-to-playback. Alignment is conditional (“when available”), so preserve transcript timing fallback. The model-level 100 ms number cannot stand in for either measure.
