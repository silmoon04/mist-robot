# Voice expressiveness and cloning options for MIST

Implementation follow-up: the v4 Turbo multi-context endpoint has now been
verified with this account and voice. The experimental live preset is wired,
including delivery tags and interruption guards. A fresh 12-render paired run
measured median text-to-first-audio of 382.5 ms for Flash and 211.5 ms for v4,
with six renders each. v4 provided character alignment for a median 71.1% of
audio bytes, so the default remains Flash. These are small-sample transport
timings, not listener quality scores or end-to-end response latency. See
`../results/brain-quality-20260929/VERIFICATION.md` and `voice-after/results.json`
under that result directory. The sections below preserve the research and
candidate-selection rationale from before implementation.

Checked 2026-09-29. Provider model names and API behavior change quickly; the links below are first-party docs checked on that date. Latencies in provider docs are inference/server-side figures unless explicitly marked otherwise. They do not include LLM time, phrase buffering, network, audio transport, or browser playback.

## What MIST does today

`brain/duplex/tts.py` keeps a single ElevenLabs WebSocket open on `eleven_flash_v2_5`, uses the configured Eleven voice ID, sends phrase-sized flushed chunks, and measures from the first non-whitespace text delta to the first returned audio byte. The generation schedule is `[120, 160, 250, 290]` characters. The delivery map changes only `stability` (neutral .5, warm .4, gentle .65, bright .3, serious .75); the code itself correctly labels named emotion as not guaranteed. This metric is TTS text-to-audio latency, not end-to-end response-to-playback latency.

`affect_director.py` proposes only `neutral`, `warm`, `gentle`, `bright`, or `serious`; it runs in parallel and returns evidence-grounded JSON. `affect_controller.py` does not hold up the speaker while the proposal runs. That is a useful policy/intent input, but it is not yet mapped to a model-supported emotional direction in the speech text. A delivery stability hint cannot guarantee a named emotion.

MIST already has a successful one-shot `eleven_v3_conversational` multi-context probe in `brain/harness/probe_affect_prosody.py` and its 2026-09-24 results: plain text and `[curious]` / `[excited]` requests completed with this same Eleven voice ID; tagged samples measured 0.516 s and 0.344 s from text send to first provider byte with >99% timed-byte coverage. These are two samples, no browser playback timing, and no human listening scores, so they prove endpoint/tag/alignment compatibility for a prototype but not better perceived expressiveness or typical latency. This makes v3-conversational an immediately testable choice while v4-Turbo is the current model upgrade to probe.

### Local option

**Resemble Chatterbox** is worth a local quality prototype if the machine has a suitable GPU and MIST can tolerate generation/serving work. Official repo supports reference-audio cloning, expressive `exaggeration` tuning, Turbo/Nano variants, and tags such as `[chuckle]`. The core documented API generates a waveform, not a maintained official streaming transport. Treat third-party “streaming” wrappers as unproven and measure first chunk on MIST hardware; an older official issue/thread is not a latency guarantee. Sources: [official repo and examples](https://github.com/resemble-ai/chatterbox), [official issue tracker](https://github.com/resemble-ai/chatterbox/issues/314). 

## Immediately testable changes on the current Eleven setup

1. **Run a small blind listening test with existing Flash first.** Hold transcript and voice fixed; compare current stability values and phrase scheduling. Keep the score separate for emotional fit, identity similarity, naturalness, intelligibility, and latency. This establishes whether hints already help.
2. **Use delivery text only on a model that supports it.** For v4 Turbo, have the existing affect decision map to a small approved set of short tags at phrase/utterance start (e.g. warm → `[warmly]`, bright → `[excited]`, serious → `[serious]`) and pass through a strict allowlist. Do not send bracket directives into Flash v2.5, whose documented controls are different and which may treat literal tag text unpredictably.
3. **Prioritize v4 Turbo, with v3 Conversational as the tested fallback.** Verify the exact model ID against the account's model list, then smoke-test a v4 Turbo single-context TTD connection with the existing voice ID, `[curious]` / `[excited]` tags, PCM 24 kHz, `sync_alignment`, flush/close behavior, and MIST interruption/reset semantics. The existing probe already validates those tags, PCM, and alignment on v3 multi-context TTD; it does not validate v4 or the single-context endpoint in production. Current general model docs and German TTD guide show v4 Turbo while current English TTD pages still say v3-only; that is an API documentation mismatch to resolve with the account check and one controlled request. TTD buffers around 40 characters / 8 words; `flush` can force short text, so listen and measure that trade-off. Leave Flash as fallback. Sources: [multi-context TTD reference](https://elevenlabs.io/docs/api-reference/text-to-dialogue/ttd-multi-websocket), [current model list](https://elevenlabs.io/docs/overview/models), [English TTD guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/realtime-tdd), [German TTD guide](https://elevenlabs.io/docs/de/eleven-api/guides/how-to/websockets/realtime-tdd), and MIST's [probe script](../harness/probe_affect_prosody.py) / [results](../results/dual-model-harness-20260924/prosody/results.json).
4. **Treat cloning as vendor-specific.** The existing Eleven `voice_id` cannot be assumed to exist at Cartesia, Fish, Inworld, or local Chatterbox. If testing a different provider, create its clone from the same authorized clean reference recording, store its new provider-specific voice identifier, and compare the cloned output. Don't clone from synthesized output when original source audio is available. Eleven docs say the source sample's delivery is reflected in a clone, so test a naturally expressive sample rather than a monotone one. Sources: [Eleven voice guidance](https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech), [Cartesia clone guidance](https://docs.cartesia.ai/build-with-cartesia/capability-guides/clone-voices), [Inworld clone guidance](https://docs.inworld.ai/tts/instant-voice-cloning).

## Blind A/B protocol

- Prepare 12–20 short MIST utterances with identical exact text: warm acknowledgement, curiosity, light delight, serious/careful answer, gentle empathy, neutral fact, plus neutral controls. Include short replies and one multi-sentence reply because buffering/context effects differ.
- For each vendor/model, use the same authorized source recording and have each vendor make its own clone. If that is not currently possible, label that run “voice quality unavailable” rather than comparing unrelated stock voices.
- Render each text in randomized order. For Eleven compare current Flash v2.5 with v4 Turbo; challengers should be Cartesia Sonic 3.6, Fish S2.1-Pro, and Inworld TTS-2. Record model, region, connection warm/cold state, output format, instruction/tags, chunk schedule/flush behavior, and provider voice ID (never keys).
- Have at least three listeners rate anonymized clips on 1–5 scales for (a) intended emotion fit, (b) conversational naturalness, (c) MIST voice identity similarity, (d) intelligibility, and (e) unwanted overacting/artifacts. Ask “which sounds most like MIST?” separately from “which expresses this turn best?”
- Measure monotonic timestamps for response-start → first LLM text, first TTS request text, first provider audio byte, and first browser-played sample; also measure p50/p95, total audio duration, interruption time, and dropped/late chunks over at least 30 warm and 10 cold runs per finalist. MIST's existing `first_byte_s` begins at first non-whitespace TTS text, so add/report response-start and playback-start externally to compare whole interaction. Do not compare that number directly with vendor TTFA.
- Choose a candidate only if emotion-fit improvement is consistent across speakers/listeners and it keeps an explicit p95 response-to-first-playback target; compare costs and integration effort after listening/latency shortlist.
