# Preview runner

The page uses the original catalog palette and native face atlas. Scene and profile controls restart at time zero for a reproducible comparison. Nothing plays automatically. Reduced motion disables incidental idle blinks and glances; explicit playback retains native speech cels and necessary 400 ms expression transitions. Space toggles playback outside interactive controls; I interrupts. Native buttons also work with Tab, Enter and Space.

`transport.mjs` schedules the native WAV in segments. An inserted delivery gap freezes clip time while the authored scene advances, then resumes from the same clip offset. `getOutputTimestamp().contextTime` supplies scene time when supported; `AudioContext.currentTime` is the fallback. Scene time cannot move backward when output timestamps begin reporting or regress. These are browser scheduling clocks, not measured acoustic latency. The UI calls the adapter at 15 fps.

`playback.mjs` owns the lifecycle used by the page and its focused tests. Reset retires audio and resets the scene clock before resetting the adapter's blink epoch. It establishes attentive intent and clears the old transition at scene zero, so replay uses the same deterministic poses.

Listening state keeps the latest persistent emotional intent. Interruption immediately retires the sampler and every audio source, cancels finite reactions, and begins the native return to that intent. It does not replace concerned or reassuring intent with quiet-listening. The earlier direction proposal for a quiet-listening replacement is superseded by this policy. A needed return transition lasts 400 ms, or six native frame periods, rather than waiting 400 ms and then starting it. The next 15 fps update renders completion, so scheduling quantization can add up to one frame period (about 67 ms), before any browser event-loop delay. A face already at its persistent intent settles immediately.

Pause and spontaneous audio suspension release audio sources and close speech. They clear incidental half-blinks and allow a needed reaction return to settle on real elapsed wall time while the scene and recording stay frozen. At completion the short recovery interval stops. The face clock carries the elapsed recovery offset into resume; no future timestamp is drawn and then followed by an earlier one. Resume during recovery reattaches the active sampler at the recovery boundary, so audio cannot continue with a permanently closed speech mouth. Scene end also settles the face before stopping its last interval.

Resume recreates the remaining audio segments from the frozen clip position. An interrupted recording stays canceled on resume. Pause, interruption, scene replacement, replay and page teardown cancel pending starts as well as active sources; an obsolete resume rejection cannot fail the current scene. A context must actually reach running state before sources are scheduled.

The displayed response is the exact full recording transcript. Interrupted playback changes its label so the remaining transcript does not imply that those words were heard. The timing inspector records cue provenance and shows estimated timing as estimated. Its target becomes rest with silence provenance when playback is canceled. It shows scene and face clock milliseconds separately. Commands skipped after interruption appear as canceled-event; subsequent simulated context remains visible.

Notes capture scene ID, scene time in milliseconds (`time`), audible clip position in seconds (`audiblePosition`), preview version and profile when the note is first created. Subsequent typing updates that same moment. New moment starts a separate note. Browser local storage persists notes; Export notes exposes all saved JSON, including after reload. Export version 1.0.1 adds explicit unit metadata and preserves the existing note fields and storage key. Copy JSON falls back to selectable text when clipboard permission is unavailable, and download remains optional.

Run `node --test preview/transport.test.mjs preview/playback.test.mjs` from `character-preview/`. The transport checks use an injected AudioContext. Playback checks exercise the actual adapter and native state engine with an injected clock and renderer; they read the existing manifest. `window.characterPreview.snapshot()` is a read-only browser diagnostic covering scene/face time, audio, face, pending starts, recovery, loop/source counts, events and notes. Independent browser acceptance owns screenshots, observed timer behavior, and the final visual verdict.
