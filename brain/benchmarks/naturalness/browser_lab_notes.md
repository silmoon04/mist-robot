# Browser capture contract

Current capture revision: `2026-09-24-continuous-recorder-v2`. Each browser result and `window.mistLab.state` include this identifier. The server's source manifest records the exact file hashes for a run; start a new server output directory after changing the capture code.

The lab uses the production `Playback`, `ExpressionPolicy`, wording-based automatic expression selection, and current handdrawn face renderer. It sends prerecorded PCM to the production `/voice` WebSocket. It never calls `getUserMedia` or sends API credentials to the browser.

The hosting server provides these loopback routes:

- `GET /lab` and `GET /lab.js` serve the page and module.
- `POST /lab/setup` sets the pairing cookie and returns `{fixtures: [...]}`.
- `POST /lab/begin` receives `{case_id}` and resets the per-case runtime before a new WebSocket opens. It must wait until any previous voice session is released.
- `GET /lab/fixture/{filename}` serves a PCM16, mono, 16 kHz RIFF WAV. Filenames may contain relative directory components.
- `POST /lab/result` stores the JSON capture, identified by `case_id`.
- `POST /lab/audio?case=ID&format=webm&kind=audio` receives the browser's actual MediaRecorder bytes. `kind=face_video` receives a second WebM with the production canvas and the same rendered audio. Keep both files. The actual MIME type is in the request Content-Type; formats may be `ogg` or `mp4` on browsers without WebM support.
- Optional `POST /lab/seed` receives `{case_id, text}` and starts assistant speech for a `{type: "seed_text", text: ...}` step. This route must start speech asynchronously and return promptly, since the next step can interrupt it.

A fixture has `{id, steps, tail_ms}`. Each audio step has `{file, trigger, delay_ms, role: "user"}`. Supported triggers are `ready`, `after_playback`, `after_idle`, `after_input`, and `immediate`. `after_input` uses the preceding input's end time. The other action triggers are relative to the preceding step's action start. `after_playback` waits for the first production `Playback.onStart` since that action, including starts that happened while the previous input was still streaming. It excludes epoch/sequence pairs that were already observed or queued when that action began, so old speech cannot stand in for the new response. `after_idle` waits for current playback to drain when the action began during playback; otherwise it requires playback after the preceding action, then its completion. A missing trigger fails the case after a bounded wait; it does not silently send at a guessed time. An optional `trigger_timeout_ms` changes the default 30-second wait. `playback_index` selects the nth packet start after the anchor, starting at 1.

For `after_idle`, an accepted `audio_reset` also ends playback when it clears a queued epoch/sequence that was actually observed by `Playback.onStart`. The capture records this as `playback_cancelled`, separate from a natural `playback_idle` callback. A reset of an empty queue, a reset before the first observed playback start, or a stale reset cannot satisfy the trigger. This lets a follow-up input proceed after interrupted speech without inventing a completed response when no speech started.

Optional steps `{type: "background", question: ...}` send the production `start_background` message. Optional seed steps use `/lab/seed`. `{type: "pause", duration_ms: ...}` waits without submitting speech. Each fixture can set `timeout_ms` (default 120 seconds) and `startup_timeout_ms` (default 30 seconds).

The final `tail_ms` is an observation window, not proof that the assistant finished. The capture extends while assistant generation or playback is pending, then waits for two seconds with no queued audio or new generation/audio events. Assistant transcript deltas mark generation active; `transcript_done` marks it complete, and an audio reset clears the interrupted generation. Seed requests, user transcript completion, and thinking/checking states also mark a response pending. A temporary queue gap cannot satisfy the drain while generation remains active. The maximum extension is 20 seconds; `post_tail_drain_ms` can shorten that limit. `playback_drain` records whether the window was extended, its duration, and timeout. `capture_truncated` flags an unfinished or unsettled capture. Remaining scheduled audio, generation status, and active background jobs are recorded at the boundary. `complete` still refers to completion of the test schedule, not a quality score. The metric `next_playback_after_input_end_ms` names the nearest subsequent playback; it does not attribute that playback to the input.

PCM steps accept `role: "user"` and `role: "synthetic_noise"`. Both traverse the same audio input path; the role remains attached to the input and its start/end events. Synthetic noise is a procedural non-speech surrogate, not a recording of coughing or a person.

A user `transcript_done` marked with both `backchannel: true` and `floor_preserved: true` does not request another assistant reply. The generation observer leaves the existing generation state unchanged for that event. It neither creates a pending response after assistant completion nor clears a response that is still generating.

A fixture with `digital_echo: {gain: 0.2, delay_ms: 120}` enables a synthetic echo loop. It captures the actual Web Audio recording tee through a MediaStream source, applies a DelayNode and gain, filters at 7 kHz, and downsamples to 16 kHz in an AudioWorklet. The worklet emits 320-sample blocks; any active PCM fixture is added to each block with saturating PCM16 conversion, then submitted through the production mic message. The loop remains active throughout the tail and drain. Its speaker output is zero, so the capture branch cannot play a second copy of the response.

The echo's nominal delay is measured from the render graph and includes additional MediaStream/worklet buffering; it is not a measured room impulse response or acoustic speaker-to-microphone delay. Browser microphone echo cancellation is bypassed. Echo captures include per-packet RMS, source processing time, mixed-input RMS, clipping counts, and a count of non-silent echo packets. A missing worklet or failed capture produces an error. A run that contains no non-silent echo is flagged instead of counted as a valid echo test. These cases test model behavior under synthetic digital feedback; physical microphone echo handling remains unmeasured.

All event times are milliseconds since the case's `performance.now()` origin. The capture also records that origin, `performance.timeOrigin`, and wall-clock start time. Scheduled output times and `Playback.onStart` are explicitly software estimates, never acoustic observations. Audio source creation, start, stop, and ended callbacks are recorded without retaining base64 PCM in the event log. Every actual source is connected once to the speaker and once to a MediaStreamDestination; there is no second speaker path.

A zero-valued ConstantSource is connected only to the MediaStreamDestination before either recorder starts. It remains active until both recorders stop, keeping the recording track active during leading silence, inter-sentence gaps, and the observation tail. It has no speaker connection. `recording_clock` records its lifetime. Each recorder includes its browser-clock start, stop request, encoder start/stop callbacks, flush delay, and chunk timecodes. `end_ms` is the stop request time, so encoder flush time cannot masquerade as captured audio.

Recordings from revisions before `2026-09-24-continuous-recorder-v1` have unverified audiovisual alignment: the MediaRecorder audio track can omit intervals while no source is active. Preserve those original files and their audit findings. Their browser event timestamps remain separate software observations; do not align their waveform samples to those timestamps by assuming the omitted duration was recorded silence. New recordings also begin with `media_alignment.status: "unverified_pending_media_audit"`. Verify decoded audio/video PTS continuity and duration against the recorder interval before using a recording for timeline or lip-sync analysis. The continuous source is a capture correction, not an automatic claim that media alignment passed.

The face timeline samples at 15 fps and contains the production snapshot's expression, mouth cue, transition, activity, renderer readiness, policy state, and output clock. Geometry is omitted to keep JSON manageable. Face video captures the actual production canvas at 15 fps. It is marked unavailable if canvas capture or a supported MediaRecorder format is absent. No substitute video is manufactured. The first and last actual canvas frames are also saved as PNG data URLs. Each frame carries its own observation time, so timer throttling and missed sample intervals remain visible.

`complete` means that the input schedule and observation window completed. It is not a naturalness score or a quality pass. Failed runs retain their events and recordings. Raw WAV inputs and expected answers stay in the fixture manifest; transcripts, model errors, warnings, interruptions, and background events remain in the capture. A hidden tab is recorded as a timing limitation. Upload failures leave browser download links, and the run list reports the failure.

Start one case or all cases with the page buttons. `?ids=comma,separated,ids` sets the selected case and limits the Run all button to those IDs. A single click resumes AudioContext before any asynchronous setup. Each case uses a fresh WebSocket and face instance. Closing the socket, stopping playback, and stopping the recorder are bounded; the next case does not start before closure. The page exposes `window.mistLab.run(ids)`, `stop()`, `results`, and `state` for a browser automation client, plus `window.labPromise` and `window.labStatus`. `run` still requires an AudioContext user gesture on browsers that enforce autoplay policy.
