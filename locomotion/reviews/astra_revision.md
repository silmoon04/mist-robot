# Astra revision

Implemented the A1–A8 software corrections for independent re-audit. The final Python run passed 100 tests and 12 subtests in 20.67 seconds; its two warnings concern unbounded Gym observation boxes. Both ESP32 variants compiled, browser JavaScript parsed, and the loopback dry-run exercised arm, position-target crawl, disarm, stale-arm rejection, STOP and clear. The shipped profile remains unconfigured. No device was flashed or actuated.

## Changed behavior

- A1: `provenance.py` supplies a shared content envelope, required source/CAD/mesh hashes, observation contract and checkpoint/replay sidecars. Training freezes before workers and checks after setup and around evaluation/checkpoint writes. Resume needs an identical experiment, matching SAC replay and a new output directory. Continuation uses recorded fresh seed streams; transfer resets ranking and SAC replay but still requires compatible source and observations. Consumers reject stale or missing provenance.
- A2: host and firmware invalidate prior arm intent on disarm/stop. Duplicate arms fail. Browser departure sends STOP even while arm is pending. Cumulative per-joint slew credit has one initial two-tick allowance, tested at 10, 50 and 500 requests/second over equal time. Dry-run crawl uses `position_targets` with the same nominal payload and position feedforward.
- A3: simulation startup uses unavailable zero vectors, never fabricated current truth. The same delivered readings feed actor and gait. Missing/stale readings latch an episode stop until reset; `none` is explicit open loop. Sensor gap/reboot recovery restores observation availability without arming. Phone pairing requires timestamps within 20 ms; moving-pan output is refused until timestamp alignment exists. Sensor mode/profile passes through training, validation, evaluation, benchmark and remote; phone cases require positive payload.
- A4: resolved config reaches model, gait and servo. Voltage/gain/deadband ranges, nominal voltage, thermal coefficients, encoder quantization/velocity noise, terrain height range and restitution are consumed. Invalid physical values or clocks fail before physics allocation. The supported clocks remain 1000/50 Hz. Legacy unused IMU noise fields were removed; sensor profiles own that noise contract. Nominal gravity feedforward remains independent of scenario perturbations.
- A5: exporter calls the pinned profile audit, rejects altered URDF/manifest hashes and fixed-R7 geometry changes before writing, and refreshes config/profile/pending-measurement hashes. Yaw limits are restricted to the principal interval. Alternate profiles remain kinematic audits, not dynamic robot selection.
- A6: one `simulation-walking-v2` acceptance module requires at least 19.2 seconds, completion, finite metrics, no loaded body/nonfoot contact, no fall/sensor fault, progress and bounded path/yaw/tracking/saturation. Stop, clockwise/counterclockwise, combined and transient commands are included. Only eligible validation candidates compete on reward. Validation owns base 1,000,000; final testing owns 2,000,000, writes separate evidence and refuses to overwrite it. Sensitivity remains development evidence and preserves the environment’s 0.1 N contact meanings.
- A7: six jobs have a common 1,001,472-transition budget and paired but disjoint repetition bases 42, 100042 and 200042. Worker overrides must retain rollout divisibility. Records include actual transitions and optimizer updates. Setup consumes the complete Python 3.11 CPU version lock, including websocket-client and native MuJoCo. `uv pip check` confirmed the installed 41-package environment; a clean network reinstall was not performed. CUDA needs a separate environment and Torch build.
- A8: remote accepts explicit verified checkpoint paths and shows sensor validity, policy status and seed. The development sensitivity plan has 239 cases, including sensor delay/dropout/bias and independent phone masses. The README retains the missing physical policy-runner boundary.
