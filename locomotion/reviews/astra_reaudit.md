## Residual concerns

1. `--transfer` loads the complete old SB3 model, including optimizer state and most old algorithm settings, then records the new requested experiment. Changed learning rate, batch size or PPO rollout parameters are not applied to the loaded object, though the effective-parameter file exposes the discrepancy. This is a P2 transfer-path defect. Do not use transfer for this fresh comparison. A later fix should construct a new model from the requested parameters and copy compatible policy weights, or reject parameter changes and accurately label optimizer continuation. The fresh-run path is unaffected.

2. Hardware measurement-age estimates use the minimum observed arrival-minus-source-clock offset. That can detect added queue delay relative to the best observed arrival, but cannot measure constant one-way latency or initial backlog. MPU recovery also reanchors after a receive gap. Phone defaults remain 100 ms on hardware and 200 ms in simulation. These are unresolved deployment timing assumptions, not grounds to invent synchronized clocks or measured Mi 9 SE latency. Keep the physical gait gate closed and bind a measured timing profile before implementing the policy runner. The simulator now stops on prolonged loss and no longer silently trains through it.

3. The common scorer's reported criteria are fixed engineering targets, not measured robot tolerances. Some comparisons use numeric literals alongside the `CRITERIA` dictionary; current values agree, but a future threshold edit must change one canonical value or add a consistency test. Do not tune them against the untouched test matrix.

4. Transient commands are assigned to `env.command` immediately before inference, while the observation passed to the policy still contains the previous step's command. The gait sees the new command one 20 ms control tick before the actor. This is a bounded command-update latency in the current evaluation/remote path, not a fresh constant-command training blocker. Document or unify the update order before claiming deployment parity. The policy's sensor and actuator signals already have other explicitly modeled delays.

5. The baseline and learned controller still depend on estimated link/body masses, motor response, primitive contact geometry and gravity/support feedforward. The independent MuJoCo fixed-leg comparison can test imported frames and unloaded/loaded dynamics; it cannot validate full-body contact walking or the actual servo. Alternate design profiles remain kinematic audits. GPU physics training and the hardware observation-to-policy-to-calibrated-target runner remain unimplemented boundaries.

The initial critique remains a historical record. Its items should be read with this closure and the reviser's evidence, not treated as current unfixed findings in the fresh-training path.
