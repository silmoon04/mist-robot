# Sol 08 training and queue review

Reviewed 2026-10-12. Scope: train.py, run_job.py, run_training.sh, train_smoke.sh, benchmark.py, training_queue.json, setup_cpu.sh and requirements. Core source is still under revision. No training was launched and no checkpoint is qualified by this review.

## Findings requiring revision

1. **P1: The source envelope omits sensor behavior and permits incompatible resume.** `train.py:31-42` hashes seven files but omits `sensor_sim.py` and its imported `hardware/sensors.py`. A sensor revision can pass the runtime guard. Missing listed files are silently omitted. `train.py:282-306` snapshots today's hashes, then loads any checkpoint; it never compares checkpoint provenance with the original run. SB3 space matching cannot detect a changed observation meaning, reward, mass, noise model or gait. Reject missing required files and mismatched source/config/environment hashes before environment allocation or output writes. Give every checkpoint a sidecar containing immutable run identity, checkpoint SHA256, algorithm, timestep, effective parameters and source envelope. Compare that envelope on resume. An intentional incompatible transfer must create a separately labelled run, never continue old best-selection history.

2. **P1: Resume can mix incompatible validation scores and silently discard SAC replay.** `train.py:322-323` imports an output directory's old best reward without comparing validation suite, checkpoint lineage or environment settings. A new suite may never beat an irrelevant old score. `train.py:303-310` loads a filename-associated replay buffer without provenance checks and accepts absent replay by printing a message. SB3 restores weights and timestep while an empty replay changes the experiment. Require checkpoint/replay hash association and matching observation/action/environment envelope. Fail when a continuation lacks replay; allow explicit fresh-replay transfer only as a new experiment. Record loaded buffer size, source hash and learning-start semantics. Avoid stale `_replay_buffer.pkl` companions when saving a same-named model without replay.

3. **P1: Sensor configuration cannot be selected or reproduced through the training CLI.** MistEnv supports `sensor_mode` and `sensor_profile`, but `train.py:272` and evaluate construct environments without either. Add `--sensor-mode {mpu6050,phone,none}` and a validated JSON/profile-file override, propagate resolved values into training, validation and benchmark, and hash the resolved profile. Allow explicit validation sensor settings only when recorded as a deliberate distribution shift. Phone mode requires explicit positive phone payload in training and every validation case; current `[0,0.155]` defaults contain an incompatible absent-phone case. Expose explicit phone presence/mass independently of sensor choice and fail before running for incompatible combinations. Open-loop `none` needs its own planned job/profile, never silent fallback.

4. **P2: Matched requested steps are unequal actual budgets.** All queue jobs request 1,000,000 transitions with four workers. PPO defaults to a 2,048-transition rollout, so it finishes at 1,001,472; SAC finishes at 1,000,000. Smoke PPO's 2,048 budget is divisible by its 256 rollout and is matched. Set queued budgets to a common rollout multiple, for example 999,424, and record expected actual transitions in the manifest. Enforce or recalculate divisibility after `--n-envs` overrides. SAC performs one gradient step per vector step, about one update per four transitions, while PPO performs five epochs over each rollout. State that comparison matches transitions, not optimizer work or wall time; retain those measurements separately.

5. **P2: Three nominal training seeds have overlapping environment streams.** Worker ranges are 42-45, 43-46 and 44-47 for both algorithms. Paired algorithms should share each run's worker seeds, but independent repetitions should have disjoint streams, such as run bases 42, 1042 and 2042 or SeedSequence-derived streams. On resume, `set_random_seed`, factories, `env.seed` and SB3 load seed restart the original stream. The text acknowledges lack of bitwise continuation but not the resulting repeated episode draws. Either persist RNG/environment state or assign and record a fresh continuation stream; never describe reseeding as uninterrupted training.

6. **P2: Validation is separate from initial training seeds, but an untouched test suite is only a promise.** Queue validation uses 64 episodes (four terrains x two payloads x four directions x two repeats), seeds 1,000,000 through 1,000,063, reused for selection. There is no standalone test evaluator or test-seed guard. Add an evaluation-only checkpoint command with a distinct frozen suite and test range, such as 2,000,000 upward. Never rank checkpoints or tune parameters from test results. Record ordered cases and suite hash; positional case numbering currently changes seed assignment if case order changes. Training/evaluation guards separate initial seeds only, not a saved full seed plan.

7. **P2: Best checkpoint uses reward alone despite reporting safety and tracking signals.** `ValidationCallback.run_validation` selects only `mean_reward`; fall fraction and velocity error are recorded but do not constrain selection. Add aggregate velocity/tracking/saturation metrics, per-direction and per-terrain failures, and a documented simulation acceptance rule. Gate on finite metrics and a frozen maximum fall rate and velocity-error threshold, then rank accepted checkpoints; keep rejected candidates visibly unqualified. Choose thresholds from an explicit requirement, not invented values. Hardware qualification remains separate.

8. **P2: Setup does not consume the available lock.** setup_cpu.sh pins CPU torch, then installs requirements.txt; indirect packages can drift although requirements.lock.txt exists. The lock also lacks websocket-client present in requirements.txt. Resolve one complete Python 3.11 CPU dependency lock including websocket-client, install that lock, and record artifact hashes/index provenance plus Python version. Preserve a distinct explicit CUDA setup and never imply CPU torch can satisfy a CUDA request. `checked_device` correctly rejects automatic device selection and unavailable CUDA, and allocates a tensor on the requested device before training.

## Training3seed plan after source freeze

Prepare six immutable candidate jobs: PPO and SAC paired across three disjoint run seed streams, common transition budget, same frozen training distribution and sensor profile, fixed validation suite, recorded worker count and optimizer parameters. Measure CPU throughput first with the exact resolved sensor/profile settings, then choose workers and recompute budget before freezing the manifest. Schedule only after the Sol/Astra corrections and guards pass. Keep evaluation-only untouched test jobs separate and run them once on the selected candidate from each repetition. Aggregate across three runs; do not call one best seed the algorithm winner.

## Reproducible source envelope

Include trainer and imported simulation/control modules, `sensor_sim.py`, `hardware/sensors.py` and relevant package initialization files, config/model inputs, resolved external sensor profiles, generated-model recipe, queue/job arguments, complete dependency lock, Python/package versions and selected device. Resolve the actual `--env-module` origin rather than hashing only default MistEnv. Use sorted relative paths and content hashes with an envelope schema/hash. Capture before importing or spawning workers and check after setup as well as before/after evaluations/checkpoints. Tie checkpoint, replay and evaluation-suite hashes to it. Source changes during imports/workers before the current snapshot must not go unnoticed. Git commit and dirty status are useful provenance but do not replace content hashes.

## Checks performed

Python compilation of train.py, run_job.py and benchmark.py passed without importing runtime dependencies. `bash -n` passed for locomotion scripts. `run_job.py --job ppo-seed42 --print-command` generated the expected command and did not create a run. A small AST-extracted source-hash guard probe rejected unequal expected hashes and confirmed both sensor modules are absent from the current envelope. Queue arithmetic confirmed PPO's expected 1,001,472 versus SAC's 1,000,000 transitions and the overlapping worker seed ranges. No physics rollout, optimization, paid resource or training job was started. CUDA behavior was inspected, not exercised on hardware.
